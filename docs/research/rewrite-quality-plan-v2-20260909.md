결론짓지 않는다. 다만 **"계획의 절차를 통과했다"고는 말할 수 없다**는 사실만
남긴다.

## 0. 무엇을 왜 먼저 구현하는가

**첫 제품 실험 후보를 “문장 길이/CV 강제 지시 제거”에서 “원문의 장식적 과장·상투어·중복은 실제로 덜어내고, 정보가 담긴 주장·강도·조건은 지키는 편집 지침”으로 바꾼다.** 사용자가 제시한 “폭발적으로 증가합니다”가 윤문 후에도 그대로 남는 문제에 직접 대응하기 위해서다. 이것은 개선이 확인된 결론이 아니라 새로 우선 검증할 가설이다.

그보다 먼저 할 연구 작업은 **단계별 출력 추적과 ‘필요한 교정 수행’ 평가를 기존 도구에 보완하는 것**이다. 초안 자체가 수정되지 않는지, 적절한 삭제가 검증·재시도에서 되돌려지는지 확인해야 제품 수정 위치를 결정할 수 있다. 기존 도구가 이미 지원하면 새 도구를 만들지 않는다.

> 목표: 사실과 중요한 주장은 지키고, 불필요한 표현은 확실히 줄인다. 무수정도, 많은 수정도 그 자체로 성공이 아니다.

이 문서는 기존 PLAN.md·BENCHMARK.md·REPORT.md와 후속 사용자 요구를 바탕으로 수정했다. 이번 개정에서는 원격 dev 조회, 최신 코드 감사, 모델 연결 확인, 품질 실험을 새로 실행하지 않았다. 현재 SHA·실제 모델·성능 수치는 unknown이다. 과거 접근 실패가 지금도 지속된다고 가정하지 않는다.

## 2. 편집 계약: 무엇을 지키고 무엇을 덜어내는가

### 2.1 항상 보호할 정보

주체·행동·대상·수치·단위·시점·고유명사·전문 용어뿐 아니라 부정, 조건·예외, 적용 범위, 불확실성, 인과관계, 비교 대상, 의무, 위험 수준과 중요한 주장 강도를 보존한다. 숫자 목록만 같아도 주체나 조건에 연결된 값이 바뀌면 실패다.

직접 인용, 타인에게 귀속된 평가, 의도적인 슬로건·작품 표현, 문서 목적에 필요한 경고·강조는 별도로 보호한다. “반드시 전원을 차단”의 ‘반드시’, “지수적으로 증가”의 ‘지수적으로’를 상투어처럼 삭제하지 않는다.

### 2.2 제거·축약할 표현

문서 목적상 불필요하고, 덜어내도 정보·중요한 주장·발화 기능이 유지되는 상투적 도입, 중복 설명, 내용 없는 강조를 제거하거나 축약한다. 단어를 다른 과장 표현으로 바꾸는 것만으로는 문제를 해결했다고 평가하지 않는다.

다만 **홍보적 평가를 중립화하는 것은 때로 평가적 태도를 바꾸는 편집**이다. ‘혁신적’ 같은 평가를 모두 의미 없는 장식이라고 단정하지 않는다. 중립 설명문으로 정리하라는 작업 목적이 명시된 경우에만 비귀속적 홍보 수사를 완화하고, 이를 `authorized_rhetorical_normalization`으로 기록한다. 완전한 문장 의미 동일성이라고 부르지 않는다. 사실적 주장과 중요한 입장을 삭제하는 권한으로 확대하지 않는다.

실험에서는 문서 목적과 기대 말투를 입력 manifest에 먼저 고정한다. 새 톤 모드·자동 목적 추정기·전역 ‘담백체’ 기본값은 만들지 않는다. 목적이 불명확하면 중요한 강도와 평가를 보수적으로 보존하되, 명백한 중복까지 그대로 남길 이유로 삼지 않는다.

## 3. 실행 시작 조건과 코드·이력 점검

이 절은 실제 연구를 재개할 때 실행할 절차다. 이번 계획 개정에서 실행한 명령이 아니다.

```sh
# 저장소 root와 AGENTS.md를 먼저 확인한다. 기존 변경을 덮거나 숨기지 않는다.
git status --porcelain=v1
git remote -v
git ls-remote origin refs/heads/dev
git fetch --no-tags origin refs/heads/dev
SHA="$(git rev-parse FETCH_HEAD)"
git show --no-patch --format=fuller "$SHA"
# origin URL 및 ls-remote와 FETCH_HEAD의 관계를 기록한다.
# 아래 경로가 없어야 한다. 이미 있으면 덮어쓰지 말고 새 경로를 정한다.
git worktree add --detach ../patina-rewrite-quality-2026-09-09 "$SHA"
```

읽기 범위는 AGENTS.md, src/cli/run.js, src/prompt-builder.js, src/scoring.js, src/verification-schema.js, src/verify.js, src/features/, src/backends/, src/model-defaults.js, bin/patina-skill.js, .patina.default.yaml, patterns/, document-types/, personas/, core/, tests/quality/, scripts/, docs/research/, docs/benchmarks/다.

각 발견에 실제 commit SHA, 파일:라인, 함수와 재현 입력 ID를 붙인다. 이 문서의 함수명은 과거 자료에서 알려진 조사 후보일 뿐 최신 존재·라인을 보증하지 않는다. main·npm 배포본·서로 다른 시점의 캐시로 최신 dev를 대신하지 않는다.

rewrite-efficacy, 한국어 개선, 모델 비교, judge calibration, 기각 실험을 다음 열로 정리한다: 가설 / 변경 변수 / 코퍼스·분할 / 생성·판정 모델 / 결과·실패 / 제품 채택 여부. H-RHETORIC과 동일한 실험이 있었다면 가설·측정·데이터의 차이를 설명할 수 있을 때만 반복한다. 이 개정에서 새로 명시한 차이는 ‘미교정 실패’와 ‘수사 정리의 단계별 생존’이다. 기존 연구에 이미 있으면 신규성으로 주장하지 않는다.

PR #777은 실행 정합성 맥락이며 품질 개선의 증거로 쓰지 않는다. #778의 폐기 결정과 #159/#643 재개 금지를 유지한다. 과거 영어 1건의 AI 점수 100→66.7, MPS 88.9, Fidelity 91.7은 사용자 제공 단일 관찰로만 남긴다.

Codex·Claude 등 사용 예정 백엔드는 명시 모델·추론 설정의 최소 요청으로 다시 확인한다. 파일 존재·로그인 표시를 성공으로 간주하지 않고, 실패한 백엔드를 조용히 대체하지 않는다. 요청/해석/응답 모델 ID가 다르면 차단한다. 응답 메타데이터가 없으면 실제 모델은 unknown이며 모델별 효과는 확정하지 않는다. 구체 명령과 옵션은 현재 AGENTS·CLI 구현을 읽은 뒤 기록하고 여기서 만들지 않는다.

| 생성·재시도 결과는 적절한데 반환문이 달라짐 | 후처리·fallback·출력 선택 | 반환 직전 원문과 실제 반환문 비교 |
| 자연스러운 결과가 내부 점수 때문에 열세로 분류됨 | 평가 runner·집계기 | 품질 측정과 탐지 점수 분리, 생성 개선으로 포장 금지 |

한 원인만 억지로 지정하지 않는다. 최초 문제가 발생한 단계를 primary_cause로, 후속 문제를 secondary_causes로 기록한다. 증거가 모자라면 unknown이다. 프롬프트 변경은 초안의 문제를, 검증기 변경은 오거부를 겨냥해야 한다.

측정용 추적은 가능한 한 외부 wrapper·기존 로그/영수증을 재사용한다. 필요한 임시 계측은 worktree에만 두며 모델 입력·출력 스키마·정상 반환값을 바꾸지 않는다. 기록할 것은 공개 가능한 입출력, 판정 필드와 짧은 근거뿐이다. 숨겨진 추론 과정은 요청하거나 수집하지 않는다.

## 5. 첫 제품 실험: H-RHETORIC

### 변경 범위

조사 후보: src/prompt-builder.js::buildRewriteInstructions() 또는 최신 dev에서 같은 역할을 하는 실제 함수. **편집 정책을 담은 한 구간만** 다음 의미로 교체하거나 추가한다. 지침의 실제 위치는 코드 점검 후 확정한다.

> 문서 목적과 말투를 유지하면서 정보가 없는 과장·상투적 도입·중복은 실제로 제거하거나 간결하게 고쳐라. 원문에 있다는 이유만으로 이러한 표현을 보존하지 마라. 단, 수치·주체·조건·부정·불확실성·인과관계·의무·위험·중요한 강도와 귀속된 평가를 보존하라. 수치와 기간이 규모를 이미 전달하면 중복 강조를 덜어낼 수 있다. 표현이 강도 정보를 유일하게 담고 있으면 이를 삭제하지 말고 강도를 유지해 다듬어라. 직접 인용·요청된 슬로건·이미 자연스러운 문장은 필요 없이 고치지 마라. 문서 목적상 허용되지 않은 주장·입장 변경은 하지 마라.

이 문구는 실험 지침 초안이다. 테스트 정답 문장이나 ‘폭발적으로’ 전용 치환 예시를 few-shot으로 넣지 않는다. 실제 사용 언어·기존 지침과의 조립을 점검하고 실험 전에 문구를 고정한다.

### 고정할 것

모델·백엔드·추론·출력 예산·샘플링 조건, 문서 유형·말투, 패턴 팩, scorer, MPS/Fidelity 하한, 의미 검증 프롬프트, 재시도 정책·횟수, 후처리, CV 지침을 고정한다. 새로운 구간 선택기·LLM 사전 분석·후처리 치환을 같이 넣지 않는다. 프롬프트 차이는 선언된 한 구간뿐이어야 한다.

H-RHETORIC은 추가 생성 호출을 요구하지 않는 가설이다. 토큰과 실제 재시도 횟수는 달라질 수 있으므로 실측한다. 초안이 좋아져도 현행 검증에서 거부되거나 되돌아가면 실제 제품 품질 개선으로 인정하지 않는다.

### 연구 단계를 제품 구현과 구분

우선 격리된 prompt variant로 평가한다. 제품 파일 수정·기본값 변경은 승인되지 않았다. 향후 적용 판단에서 처음 검토할 제품 변경이 위 한 구간이라는 뜻이다. 실제 trace가 검증 오거부나 실행 gate를 주원인으로 가리키면 억지로 이 후보를 구현하지 않는다.

## 6. 평가: 안전과 필요한 교정을 함께 요구

각 입력에 결과를 보기 전에 task intent, 편집 가능한 문제, 보호할 관계, 의도적 강조 여부를 명시한다. 기존 권한이 있는 코퍼스·기존 메타데이터를 우선 쓰고, 새 명세는 합성 회귀 사례로만 보완한다. 사람 모집·사람 라벨링 프로젝트를 만들지 않는다. LLM이 만든 문제 명세는 model_proposed로 표시하고 독립 판정자 간 이견은 ambiguous로 남긴다.

### 세 집단

T(교정 필요): 문서 목적상 불필요한 표현이 있는 입력. 원문 그대로 반환하면 의미가 보존되어도 미교정이다.

C(주장/강도 보호): 비슷한 표현이 정보·위험·의무·전문 의미·인용에 기여하는 입력. 무조건 삭제하면 실패다.

N(자연 원문 대조): 기존 자연 문서 또는 명시적인 합성 자연문. 과도한 개입을 검사한다. 합성 자연문을 실제 사람 글로 세지 않는다. 타당한 소규모 개선은 허용하며 모든 편집을 오류로 세지 않는다.

### 주 지표

| 지표 | 정의·주의 |
|---|---|
| 안전한 필요 교정률 | T 전체 원문 중 해당 문제를 해결하고 보호 정보를 지킨 최종 출력의 비율. 실패·롤백·판정 unknown은 확인된 성공으로 세지 않되 이유는 분리 |
| 실제 안전 교정 제공률 | 배정된 T 요청 전체 중 실제 반환된 결과가 의미·교정 조건을 모두 통과한 비율. 초안만 성공한 것은 제외 |
| 교정 생존율 | 첫 초안이 안전하게 교정된 T 중 최종 반환문에서도 교정과 의미가 유지된 비율. 분모가 없으면 null |
| 과잉 삭제율 | C/N에서 중요한 주장·강도·조건·말투/문서 기능을 부당하게 훼손한 비율. 단순 edit-distance와 구분 |
| 독립 품질 비교 | 원문·작업 목적을 제시하고 자연스러움, 목적 적합성, 상투성/반복, 목소리를 분리 평가 |

문제 구간별 교정 recall은 보조로 보고하되 원문별 macro-average를 사용해 긴 글에 가중치가 몰리지 않게 한다. 어휘 삭제율이나 편집량만으로 성공을 정하지 않는다. no-op가 C/N에서 안전한 것과 T에서 미교정인 것을 동시에 표현할 수 있어야 한다.

기존 의미 검증 통과, 독립 앵커 보존 판단, 수사 편집 허용 판단을 별도 필드로 둔다. 현행 검증 통과만으로 자연스러움 성공을 만들지 않고, 수사 평가가 좋다는 이유로 의미 거부를 덮지 않는다. 내부 AI 점수는 보조 지표이며 skipped는 점수 0이 아니다.

LLM pairwise는 사람 선호의 대리 지표다. 생성 경로·모델·처리군 이름과 내부 AI 점수를 숨기고 A/B를 균형 배정한다. 생성 계열과 다른 판정자를 우선 쓰며, 가능한 경우 서로 다른 두 판정자 계열을 쓴다. 한 판정자가 생성 모델과 같은 계열이면 관계를 노출하고 독립 근거로 과장하지 않는다. 두 판정자도 사람 검증을 대체하지 않는다.

## 7. 탐사 → 확인

### A. 진단 단계

KO 합성 8개로 현행 경로의 실제 실패가 재현되는지 확인한다. 원문·첫 초안·모든 검증/재시도·최종 반환을 남긴다. 여기서 추론할 수 있는 것은 재현된 경로와 반례뿐이며 언어별 성능이 아니다. 모델 연결이 실패하면 실패 기록을 남기고 수치 없는 계획으로 멈춘다.

### B. 단일 변수 파일럿

고유 원문 24개: KO 16 / EN 8. KO는 T8·C4·N4, EN은 T4·C2·N2. 총 T12·C6·N6다. 개발 진단과 분리하고 출처 문서/파생 관계가 겹치면 같은 cluster로 묶는다.

N0=no-op, G=일반 윤문, P=현행 dev 프롬프트, H=H-RHETORIC을 같은 생성 모델에서 비교한다. 1차는 단일 생성·재생성 없음으로 프롬프트의 효과를 분리한다. 현행 의미 검증은 동일 조건의 관측용으로 적용한다. 이 P는 CLI 전체 결과가 아니라 ‘첫 초안 기준’이다.

기본 생성 24×3=72회. 비교 H/P, H/G, H/N0, P/G를 두 판정자가 평가하여 24×4×2=192회. 사전 고정한 24개 비교-판정자 셀의 A/B 반전 +24회. **합계 288회 + 실제 검증 호출 + 연결 확인**이다. 거부·시간초과를 성공할 때까지 반복하지 않는다. 실제 호출·상한·가격 확인 없이 파일럿을 시작하지 않는다. 세부 예산은 BENCHMARK.md를 따른다.

초안 파일럿이 유망하면 미리 정한 T/C/N 각 2개, 총 6개에서 P/H의 현행 전체 경로를 추가 실행한다. 같은 생성 모델과 기존 검증·재시도 조건을 사용하고 총 호출을 센다. 이 입력은 개발용이며 최종 확인에 재사용하지 않는다.

진출 조건(제안): T12에서 P보다 안전하게 개선된 사례 최소 3개, 반대로 안전 교정을 잃은 사례 0개, C/N에서 새 핵심 의미 오류 0개, 미해결 중대한 판정 이견 0개. 두 판정자의 품질 합의 순승수가 양수여야 한다. 이는 작은 탐사 규칙이지 유의성 또는 사람 선호 증거가 아니다. 일반 윤문이 더 낫다면 숨기지 않고 이후 후보 우선순위에 반영한다.

### C. 별도 확인

사용 가능한 기존 자료가 충분하면 고유 원문 240개를 계획한다: KO160(T80/C40/N40), EN80(T40/C20/N20). 5개 문서 목적과 길이 구간을 가능한 범위에서 층화한다. 실제 확보량·출처·군별 배분은 실행 전에 확정한다. 부족한 구간을 합성문으로 몰래 채우거나 사람 라벨링을 조건으로 걸지 않는다.

P/H는 전체 CLI 경로로 비교하고 N0도 유지한다. G는 미리 정한 동일 조건의 공통 실행 driver를 제공할 수 있을 때 같이 비교한다. G에 다른 검증·재시도 정책을 쓰게 되면 별도 ‘단일 생성 기준선’으로 표기하고 최종 제공률의 동등 비교에서 제외한다. 확인 규모와 총 예산을 실행 전에 승인된 자원 범위로 고정한다.

최소 검출 효과를 보장하는 표본 수라고 주장하지 않는다. 파일럿의 원문별 차이·판정 유효율로 95% 구간의 예상 폭을 사전 검토하고, 부족하면 확인 데이터 열람 전에 계획을 수정하거나 탐사 수준에 머문다. 확인 결과를 보고 유리해질 때까지 표본을 늘리지 않는다. 반복·순서 반전·여러 판정자는 독립 n을 늘리지 않는다.

ZH/JA는 기존 자료로 탐색만 하고 KO/EN의 결론을 전이하지 않는다. 이미 본 자료는 holdout으로 재명명하지 않는다.

## 8. 적용 판단 기준과 중단 조건

아래 숫자는 실험 전에 고정할 제안 기준이지 관측 성과가 아니다. 모든 기준을 함께 만족해야 ‘적용 검토 가능’이며 이 계획 자체가 적용 승인은 아니다.

| 축 | 제안 기준 |
|---|---|
| 핵심 의미 | 현행 MPS/Fidelity 하한 유지. 후보에서 새로 확인된 핵심 주장·앵커 오류 0건. 고정 의미 보호 회귀 전부 통과 |
| 필요한 교정 | KO의 T에서 최종 안전 교정 제공률이 P보다 ≥15%p 높고, 원문/출처 cluster 단위 paired 95% 구간 하한 >0 |
| 보조 언어 | EN 별도 결과와 구간 공개. 악화 신호나 표본 부족이면 EN 적용 보류. KO 성과를 전 언어 성과로 발표하지 않음 |
| 전체 품질 | H/P 비교의 (합의 승−합의 패)/전체 확인 원문 ≥10%p, paired 95% 하한 >0. 의미 손실 출력은 품질 승자로 채택하지 않음 |
| 자연 원문 | C/N에서 새 중요 의미·문서 기능 훼손 0건. 정규화 편집량은 설명 지표이며 작은 편집량을 단독 안전성 근거로 쓰지 않음 |
| 교정 생존 | 초안 교정이 최종에서 사라지는 사례와 거부 이유를 전부 공개. 개선이 초안에만 있으면 적용 보류 |
| 실패 | 생성·검증·재시도 소진율의 관측 악화 ≤2%p. 불확실성을 별도 보고하며 넓은 구간으로 악화를 배제하지 못하면 보류 |
| 비용·지연 | 같은 모델·길이·동시성에서 p95 지연 증가 ≤10%, 검증·재시도를 포함한 평균 호출/관측 토큰 증가 ≤5%. unknown이면 비용 개선 주장 금지 |
| 판정 신뢰 | 모델 불일치·순서 편향·스키마 오류·선택적 누락이 결론을 좌우하면 보류. 판정 unknown의 낙관/비관 경계에서도 방향이 유지되어야 함 |
| 실행 회귀 | 고정 입력의 scorer·features 결과 불변, CLI-first/영수증/설정 스냅샷/출력·재시도 회귀 통과 |

0건 관측은 위험 0의 증명이 아니다. 관측 오류율의 구간과 판정 누락을 보고하고 사람 검증 부재를 명시한다. 특히 언어·장르별 작은 부분표본은 별도 안전성 보증에 부족할 수 있다. 숫자 기준을 사후 낮추지 않는다.

확인 단계에서 후보의 새 핵심 의미 오류가 하나라도 확정되거나 동일 유형이 재현되면 후보를 보류한다. 개선이 없거나 일반 윤문 대비 이점이 없으면 그대로 결론을 낸다. 운영 배포를 하지 않으므로 이번 작업의 롤백은 실험 variant 제외와 현행 경로 재실행이다. 사용자 작업물을 reset/clean/stash하거나 덮지 않는다.

## 9. 후속 작업: 관측된 원인에만 대응

P2a–d는 필수 구현 목록이 아니라 증거에 따른 분기다. 모두 구현해서는 안 된다.

검증 오거부 수정은 H-RHETORIC과 한 실험에 섞지 않는다. 같은 원문·후보 쌍에 구/신 검증을 병행 적용하고, 수사만 정리한 후보뿐 아니라 강도 약화·부정 반전·조건 삭제·인과 반전·수치 귀속 교환의 명백한 오류도 함께 테스트한다. 독립 평가자는 그대로 둔다. 오거부 감소를 글 자체의 품질 향상으로 주장하지 않는다. 어떤 허용 수사 편집도 fact-changing negative를 통과시키는 예외가 되어서는 안 된다.

## 10. 회귀 테스트 묶음

1. 문맥 최소쌍: 같은 ‘폭발적으로’라도 수치 중복/유일한 강도/인용/슬로건의 처리가 달라야 한다. 특정 금칙어 삭제 테스트가 아니다.
2. 의미 보호: 수치와 소유 주체 교환, 비교 기준·기간·조건·예외·부정·가능성·인과·의무·위험을 변형한 명백한 음성 후보는 거부한다.
3. 미교정: T의 no-op, 다른 과장어로의 교체, 무작위 문장 분할·오타 추가를 성공으로 세지 않는다.
4. 단계 추적: 좋은 초안→잘못된 거부→과장 복원→원문 fallback을 구분하고 최종 교정 성공률에 숨기지 않는다.
5. 측정 계약: skipped/timeout/auth/schema/model_mismatch를 0점·성공으로 바꾸지 않는다. missing score=null, 사건 상태와 품질 판단 분리.
6. 비간섭: 선언한 프롬프트 구간 외 byte-diff 없음. 고정 텍스트의 src/features/*·scoring 출력 불변. CLI-first, 영수증, 설정 격리의 기존 테스트 유지.

실제 테스트 파일과 함수는 최신 checkout에서 확인해 연결한다. 제품 함수나 테스트 통과를 이 문서에서 가정하지 않는다.

## 11. 산출물·보안·완료 조건

저장 위치는 연구를 실행할 worktree의 `.omo/research/rewrite-quality-2026-09-09/`다. 이번 개정 파일은 assistant 작업 공간에만 생성했으며 사용자 저장소에 저장한 것이 아니다.

REPORT.md에는 사실/가설/미검증을 분리하고 대표 성공·실패와 정확한 소스 위치를 기록한다. BENCHMARK.md 및 기계 판독 결과에는 입력 출처·ID/hash·split, SHA, 실제 명령, 모델/추론, 프롬프트/설정/패턴 해시, 단계 상태와 호출·비용·지연·판정 이견을 남긴다. PLAN.md에는 실제 근거에 따라 선택한 단 하나의 첫 제품 변경과 보류 조건을 갱신한다.

지금 하지 않을 일: 제품 기본값·의미 하한·scorer 임계값 변경, 금칙어 일괄 삭제, src/features/*의 LLM 호출, 다단계 에이전트부터 도입, 사람 모집·라벨링 및 #159/#643 재개, npm 배포/인증 변경, 결제·출시·운영 적용, 이슈/PR 생성·댓글·merge·외부 발신.
